# 设备测点管理页面：实现与测试指南

更新：2026-10-18。项目：`D:\study_software\PythonProject\smart_power_twin`。

## 1. 完成的功能与入口

本轮补齐测点的前端管理页面，复用现有monitoring后端接口和19表结构，没有新增表、权限编码或SQL脚本，也没有向你的实际MySQL导入数据。

可以从三个位置进入：

1. 右上角登录用户名 → **设备测点管理**，地址 `/admin/points`。
2. **站点与设备台账** → 具体设备操作栏的“测点”，直接选择该站该设备。
3. **三维场景配置**页上方的“设备测点管理”，保留所选站点。

支持授权站点选择、设备名称/编码查询与分页、设备测点查询与本地筛选、新增测点、调整周期/启停/阈值。观察员保持只读。页面延续海蓝、圆角、分区布局；Vue文件继续按template/script/style排列。

## 2. 先这样测试

1. 保持现有MySQL后端和前端开发服务运行。后端源码本轮未改，无需为这个页面重新建表或重新导入模拟数据。
2. 用具有 `monitor:configure` 的管理员登录，进入设备测点管理。
3. 选择朝歌服务区，再选择一台设备。也可以直接从台账中的该设备点“测点”。
4. 检查现有测点的编码、单位、类型、周期、阈值和启用状态。
5. 点击“新增测点”。已有模拟设备可能已经有active_power、temperature等编码，可新建 `test_temperature`、名称“联调测试温度”、单位°C，数据类型NUMERIC、聚合类型INSTANT。
6. 设置周期5000毫秒、陈旧时间15000毫秒。阈值可以留空；如需测试阈值保存，可填低阈值0、高阈值60。这只是联调输入，不是现场安全标准。
7. 保存后应在列表中看到新测点。创建定义不会自动产生温度读数，也不会启动模拟采集。
8. 点击新测点的“配置 / 启停”，修改周期或取消“接收该测点的新样本”，保存后重读检查。
9. 切换到只读账号，确认仍能看获授权范围内的定义，但没有新增/编辑按钮。

同一设备内编码必须唯一，重复新增会返回409，不覆盖已有测点。不同设备可以使用相同编码。保存超时或网络中断时，先点击“重读测点”核对是否已经成功，避免重复操作。

## 3. 每个字段怎么理解

| 字段 | 含义与示例 | 当前能否编辑 |
| --- | --- | --- |
| code 编码 | 设备内唯一，如active_power；小写字母开头，可含数字和下划线，最多64位 | 创建时填写，之后固定 |
| name 名称 | 中文显示名，例如“储能柜有功功率”，最多100字 | 创建时填写，当前配置接口不改名 |
| unit 单位 | kW功率、kWh电量、°C温度、%荷电状态、BOOL布尔值 | 创建后固定，避免历史读数换单位 |
| valueType 数据类型 | NUMERIC数值、BOOLEAN布尔0/1、TEXT文本 | 创建后固定 |
| aggregationType 聚合类型 | INSTANT瞬时、COUNTER累计、STATE状态 | 创建后固定 |
| directionConvention 方向 | 如“正放电、负充电”，按公司实际约定填写 | 创建后固定；未知可空 |
| sampleIntervalMs 采样周期 | 建议采样间隔；5000毫秒=5秒，范围100—3600000毫秒 | 可调整 |
| staleAfterMs 陈旧时间 | 超过此时间无新样本，读数标为陈旧；范围100—86400000毫秒，且不少于采样周期 | 可调整 |
| alarmLow / alarmHigh | 数值低/高阈值，单位与测点一致；留空为不设置，0是有效阈值，负数也可有效 | 数值点可调整 |
| enabled | 是否接收该测点的新样本 | 可启用/停用 |

INSTANT通常用于功率、温度、SOC。COUNTER用于累计电量，不能把一串累计读数直接相加当某天用电量。TEXT/BOOLEAN必须用STATE，并且不能配置数值阈值。页面提供常见测点快捷填写，只填表，不自动写数据库或设置现场阈值。

周期是平台建议配置，本轮没有向硬件下发采样频率；陈旧时间影响读数新鲜度判断，也不等于新增离线告警规则。

## 4. 与三维场景怎样连接

现在可以在前端完成：

**站点台账 → 设备台账 → 测点管理 → 场景对象关联设备 → 绑定测点 → 保存并发布**。

新增测点成功后，先保存或取消当前编辑，再前往“三维场景配置”。选择同站场景草稿，为模型对象选择本站设备并保存对象关系；然后增加该设备测点的绑定，保存绑定，最后显式发布。

场景配置页如果已经打开过，重载版本后才会读取新测点目录。不要带着未保存的场景修改离开页面。普通用户的三维页面继续读取当前发布版本，不会因为新增一个测点而自动改变模型绑定。

测点定义、模型绑定、采样是三个不同步骤：定义没有采样时显示缺测；模型有外观不代表现场设备已接入；模拟/现场来源仍由设备身份及采样入口分别校验。

## 5. 保存和停用的边界

- 编辑只提交周期、启用标志和两个阈值，不把整份查询响应提交回后端，也不改测点所属设备。
- 开始编辑前重新读取服务器定义；保存成功后重新读取列表。接口失败保留表单，方便修正或重试。
- 保存成功但随后的列表刷新失败，会明确提示“保存已成功”，此时重读即可，不应重复新增。
- 读取失败不显示为“已确认零个测点”；必须成功读取目录，才能新增，减少误判和重复编码。
- 表单编辑期间禁用切站、切设备、搜索和翻页，先保存或取消；离开页面仍会丢弃未保存输入。
- 换账号、撤销权限、切设备/站点和组件卸载会使旧响应失效，不把前一账号/设备的结果安装到新页面。
- 服务端仍强制动作权限、站点范围、编码唯一性和输入合法性；前端禁用按钮不能替代后端鉴权。
- 停用保留历史、模型绑定和告警；已存在告警不会因为停用自动恢复或关闭。后续符合条件的新鲜GOOD最新数值才参与阈值判定。
- 修改阈值不会重算历史或改写旧告警快照。清空阈值不会立即把活动事件变成恢复状态。
- 本页没有删除、批量导入、单位换算、历史回填、真实硬件控制或自动造数功能。现有编辑模式是后保存者生效，尚无多人合并编辑。

## 6. 权限及接口

页面入口要求 `site:read`、`device:read`、`monitor:read`；新增和配置额外要求 `monitor:configure`。原有模拟管理员已具备相应动作，观察员只读。若原管理员缺权，核对已有C03/C05权限脚本和角色配置，按需要手动修复后重新登录；本轮没有新增授权脚本或自动执行GRANT。

后端需要原有MySQL写开关。受限数据库连接账号还需device_point的查询/新增/更新、audit_log的新增等现有接口所需权限。这与网页登录账号角色是两层权限。

| 已有接口 | 本页用途 |
| --- | --- |
| GET /api/v1/sites | 获授权站点目录 |
| GET /api/v1/sites/{site_id}/devices | 本站设备查询与分页 |
| GET /api/v1/sites/{site_id}/devices/{device_id} | 从台账跳转时准确读取目标设备，即使其不在第一页 |
| GET /api/v1/devices/{device_id}/points | 完整测点定义，包括阈值和方向说明 |
| POST /api/v1/devices/{device_id}/points | 新增定义，不创建历史/最新值/模型绑定 |
| PUT /api/v1/points/{point_id}/config | 完整替换五项可编辑配置 |

所有ID是数据库主键字符串，不是地图路由ID、GLB对象键或设备编码。周期字段用毫秒；空阈值提交JSON null，而非空字符串或0。

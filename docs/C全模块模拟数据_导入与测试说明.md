## 2. 导入步骤

1. 在数据库工具中连接你自己的MySQL，先备份当前 `smart_power_twin`，或确认它是可恢复的开发库。
2. 执行 `SHOW TABLES FROM smart_power_twin;`，结合模块清单查看是否齐全。
3. 缺表时先完整执行C00。已有全部19表且结构与当前设计一致，可跳过C00。
4. 打开一个单独SQL连接，完整运行C01文件。选择“执行整个脚本/运行SQL文件”，需要工具支持 `DELIMITER`；不要只选中其中几条INSERT执行。
5. 成功时最后返回 `batch`、`snapshot_time_utc`、`source=SIMULATED`；随后完整运行C02核验。
6. 使用下列模拟网页账号登录，检查站点数量。前后端启动方式沿用已有配置，不需要切换到demo后端。

脚本中的 `USE smart_power_twin` 已固定库名。C00的 `CREATE TABLE IF NOT EXISTS` 只补缺表，**不会修复已有同名表的旧字段或约束**。例如旧表仍是password_hash时，应先核对结构，不能靠重复执行C00完成迁移。

## 5. 脚本怎样保护已有数据

- 先检查19表存在且为InnoDB、当前password字段存在，再导入。
- 主键根据站点code、设备code、测点code等查询，不写死自增ID。
- 原有同名账号密码、状态、角色不更新；角色动作和账号站点范围只在相应角色/账号首次新建时初始化，撤权后重跑不恢复。
- 已有最新读数不覆盖；已有告警处置和场景发布状态不覆盖。
- 现有发布场景存在时，为该站准备的模拟场景保持DRAFT；新版本模板不替换旧版本。
- 冲突时给出明确错误；业务数据插入放在事务中，失败回滚，并释放批次锁。
- 不执行DROP TABLE、TRUNCATE，不关闭外键；辅助存储过程会创建后删除。辅助过程DDL有隐式提交，务必单独连接执行，避免混入其他未提交业务事务。

脚本不需要创建MySQL登录账号。执行者需要19表的SELECT/INSERT，以及创建、执行、删除辅助存储过程的权限；C00还需要建表权限。上述是手动导入工具需要的权限，不建议因此扩大后端运行账号权限。

这是非破坏性补缺脚本，不是数据库迁移工具。它会按既定批次给已有模拟站点补充测点、采样等数据；不要将真实站点冒用这套演示编码。日后改动数据应根据变化明确选择“维护已有模拟记录”还是“新测试批次”，不靠无差别重跑覆盖修改。

## 6. 常见错误怎么处理

| 提示 | 含义与处理 |
| --- | --- |
| REQUIRE_19_INNODB_TABLES | 表不齐或引擎不符；核对C00和实际表结构 |
| REQUIRE_CURRENT_PASSWORD_COLUMN | 账号表仍是旧字段；先核对已执行的迁移，C00不能自动改旧表 |
| SIM_ROLE_CODE_CONFLICT / SIM_USERNAME_CONFLICT | 已有同名角色或账号身份与模拟集冲突；先核实，不自动覆盖 |
| SIM_SITE_CODE_CONFLICT / SIM_DEVICE_CODE_CONFLICT | 演示编码被真实台账或不同类型占用；停止混用，核对业务编码 |
| SIM_POINT_DEFINITION_CONFLICT | 同编码测点的单位、值类型、聚合方式不同；不能把旧历史解释成新单位 |
| MOCK_IMPORT_BUSY | 同批次正在其他连接运行；等对方完成，不同时重复点击 |
| PROCEDURE already exists | 前次执行失败可能留下辅助过程；先查清错误和当前是否仍在运行 |
| DELIMITER语法错误 | 当前工具把整文件当单条SQL发送；改用支持分隔符的“执行脚本/SQL文件”模式 |
| 字段不存在/外键或CHECK失败 | 实际旧表结构与本设计不一致；保留报错并核对，不删除表硬过 |

若已确认上一次导入失败、没有同批次导入仍在运行，可以在单独连接只删除遗留辅助过程后再执行修正脚本：

```sql
DROP PROCEDURE IF EXISTS smart_power_twin.c_spt_mock_all_20261016;
```

不要为了处理这个错误删除业务表或关闭外键。失败连接可关闭后重开，避免遗留会话SQL模式/时区设置影响其他操作。

## 7. 数据时间和前端显示边界

数据库采样时刻按UTC存储，C02同时提供批次北京时间。每测点15分钟一条，陈旧阈值30分钟；这套数据是一次性快照，不会自动持续更新，重复导入也不会刷新采样时间。以后需要动态演示时应由独立模拟采集程序产生新采样，监测模块按来源序号去重。

质量BAD、没有读数、采样陈旧、设备在线状态是不同概念。汇总应排除不适用的读数并显示覆盖情况；真实负荷不能把储能、光伏、充电桩和总表功率全部相加。

当前前端站点入口按授权code过滤本地场景；右侧监测读数与历史已接数据库，私有站点告警已查询数据库，其他总览/能耗仍有本地样例。详见新监测指南，尚未接入的内容不会自动替换。

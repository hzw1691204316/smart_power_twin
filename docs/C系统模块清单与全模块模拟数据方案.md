## 2. 建议按什么顺序实施

下面每项可作为一周任务，实际根据组会反馈调整。每周先完成一个可测试闭环，再进入下一项。

| 顺序 | 工作内容 | 你能怎样验收 |
| --- | --- | --- |
| 准备阶段（本轮） | 准备19表模拟数据、解释模块与关系；验证SQL导入 | 导入后能查到六站、设备、测点、曲线、绑定、告警；账号范围明确 |
| 第1周：monitoring | 测点查询、最新值、历史曲线、模拟采集入口、乱序与重复采样处理 | 查询充电桩温度与光伏功率；BAD不是0；断流变陈旧；重复采样不重复入库 |
| 第2周：twin | 场景查询和对象绑定，前端设备点击接监测数据；随后处理草稿发布 | 点储能柜显示该柜SOC；点光伏显示该阵列功率；不同站点数据不串站 |
| 第3周：alarms | 告警生成、确认、恢复、关闭，与设备定位联动 | 人工确认后异常仍存在时保持ACTIVE；异常消失后才恢复；越权不能处置 |
| 第4周：dashboard | 全国→省→市→站点汇总、历史趋势、数据覆盖率 | 汇总能追溯到设备测点；缺失/陈旧读数不会冒充实时；不同用户只汇总授权站点 |
| 后续完善 | 台账编辑与批量导入、真实设备接入、小/大型模型制作、部署 | 可以用经核验资料逐步替换模拟资产与采样来源 |

台账维护中的必要字段可在对应周补充；不把数据导入、三维制作、采集、告警全部堆在同一周。

## 5. 关系先理解这几条

```text
角色 ──角色动作关系── 动作权限
  │
  └── 用户 ──用户站点范围── 站点

高速路线 ──站点高速关系── 站点 ── 区域 ── 设备 ── 测点
                          │                      ├── 最新值
                          │                      └── 历史采样
模板 ── 站点场景版本 ── 模型对象 ── 属性绑定 ── 测点

站点/设备/测点 ── 告警事件 ── 确认用户
用户/站点 ── 操作审计
```

例如：朝歌服务区 → 充电区 → 充电桩01 → temperature测点 → 最新62.1°C → 一条温度告警。模型中的 `charger_01` 通过绑定关系找到同一台充电桩的温度测点，之后前端便能把温度、颜色和告警定位联系起来。

`site.id`、`device.id`是数据库内部ID；`site.code`、设备编码是稳定业务身份；`object_key`是GLB中的稳定对象或对象前缀。三种标识各有用途，不能相互替代。SQL按业务编码查实际自增ID，不要求你的数据库ID从1开始。

| 站点 | 类型/关联路线 | 特意准备的情况 |
| --- | --- | --- |
| 朝歌服务区 | SERVICE / S26 | 充电桩温度62.1°C，ACTIVE未确认 |
| 朝歌收费站 | TOLL / S26 | 变压器曾超温，RECOVERED但未确认 |
| 洛阳服务区·演示 | SERVICE / G30 | 光伏功率质量BAD，读数为空，不能当0 |
| 开封收费站·演示 | TOLL / G30 | 储能SOC=12%，ACTIVE已确认 |
| 许昌服务区·演示 | SERVICE / G4 | 全站采样滞后2小时，模拟离线断流 |
| 新乡收费站·演示 | TOLL / G4 | 温度告警已确认、恢复并CLOSED |

六站均为中型演示台账，每站3个区域、4台设备、16个测点。朝歌两站保留已有公开参考位置和待核验说明；其余四站为虚构测试名称及近似位置，不代表真实站场。

每台设备4个测点：

| 设备 | 四个测点 | 注意 |
| --- | --- | --- |
| ESS_01 储能柜 | active_power、soc、temperature、online | 功率正值为放电，负值为充电；SOC单位% |
| TRANSFORMER_01 变压器 | active_power、voltage、temperature、total_energy | voltage为线电压V；额定容量kVA与有功功率kW不同 |
| PV_01 光伏阵列 | active_power、total_energy、temperature、operation_state | 夜间模拟功率为0；operation_state是文本 |
| CHARGER_01 充电桩 | active_power、total_energy、temperature、online | online是0/1布尔值，不从资产ACTIVE状态推断在线 |

历史按15分钟一个样本，每个测点96条；96个时刻首尾相差23小时45分。累计电量是计数器值，某时段电量通常取有效起止差值，不能把96条累计值相加。不同电力系统的功率也不能直接相加称作总负荷，应先明确测量边界和电力平衡。

## 8. 数据准备好以后，前端会发生什么

导入后，模拟账号可查询对应授权范围。当前地图从授权台账适配站点，完整WGS84坐标才落点；六个既有模拟站点保留原入口，新站点也可从台账配置并进入地图。

私有站点已接入monitoring/twin/alarms/dashboard；场景对象与测点通过数据库绑定，告警和汇总按授权及来源读取。公开通用模型仍明确展示方案/示意，不能当现场数据。场景配置页支持新站从零建立草稿；测点定义现可在/admin/points页面新增与配置，也保留监测API。日计量和跨站历史曲线尚未实现。

这是一套静态快照，不是持续采集程序。除许昌故意滞后2小时外，快照以第一次成功导入时刻为基准；测点30分钟未更新后应判陈旧。重复导入复用原批次时间，不会把旧数据伪装成最新数据。

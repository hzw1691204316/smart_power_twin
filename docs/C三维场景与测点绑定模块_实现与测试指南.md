## 3. 怎样查看模型与读数

1. 重启一个后端进程，前端沿用原启动方式，重新登录。
2. 从河南路网进入鹤壁朝歌服务区或收费站。
3. 页面读取该站已发布场景，GLB地址来自本站场景或对应模板。
4. 点击储能柜、变压器、光伏阵列、充电桩，或从左侧目录选择对象。
5. 右侧监测只展示这个对象绑定的测点，可切换相应历史采样曲线。

左侧目录现在使用数据库对象名称与设备分类。灰色状态点表示“状态待监测”，不凭资产ACTIVE认定在线。最新值、是否陈旧和质量仍以右侧监测为准。

没有场景、没有模型资源或没有权限时会显示错误与“重新读取场景”，不会偷偷改用其他站点或固定模板来显示私有监测数据。对象没有绑定测点时会提示配置，不显示同设备的其他未绑定指标冒充绑定结果。

公开地图中未绑定私有台账的设施仍使用清楚标注的通用模板预览，不请求其他站点私有数据。

## 4. 管理员怎样编辑与发布

在站点页面左侧设备目录中展开“场景版本…对象/绑定”。普通用户只看到当前版本摘要和刷新入口；有twin:publish的管理员才显示编辑按钮。

按以下顺序测试：

1. 点击“复制为新草稿”。新版本有独立场景ID、对象ID和绑定ID，当前模型仍保持旧发布版本。
2. 在版本选择框中查看新草稿。已发布/归档版本可以查看，但不能直接编辑。
3. 每条绑定显示“对象名称·展示属性”，下拉框只列该对象所属设备的测点。
4. 修改测点，或者增加/移除绑定。界面会标记未保存，发布按钮暂不可用。
5. 点击“保存草稿绑定”。此时数据库草稿更新，正在展示的已发布场景保持原样。
6. 检查无误后点击“发布此版本”。后端校验GLB对象键和全部绑定，通过后原发布版本归档，新版本成为当前版本，页面重新加载模型和绑定。
7. 再点击同一模型对象，确认右侧显示新的绑定结果。

同一设备的两个展示属性可以指向同一个测点，但同一对象的同一propertyCode不能出现两条绑定。切换编辑版本会放弃未保存的本地修改，界面有明确提示。

建议测试时先移除充电桩的一个绑定，保存并确认当前页面仍显示原绑定；发布后确认该指标从右侧消失。然后再次复制草稿，增加该测点绑定，保存、发布，确认恢复。

第一次导入时若数据库已存在其他已发布场景，全模块模拟脚本会把新样例场景留为DRAFT，不覆盖旧场景。此时管理员可在版本列表中选择带完整绑定的模拟草稿，再发布。不要因为当前版本内容较少就删除表重建。

## 5. 写入开关与数据库连接账号

查看模型/监测不需要开启写入；复制、保存、发布需要本地配置：

```dotenv
SPT_MYSQL_ALLOW_WRITES=true
```

文件为项目根目录`.env.mysql.local`，修改后重启后端。本次没有自动更改此配置。

两层权限不要混淆：

| 权限层 | 负责什么 |
| --- | --- |
| 网页账号角色 | twin:read查询，twin:publish复制/编辑/发布；站点范围另行校验 |
| 后端MySQL连接账号 | 连接数据库、执行SELECT/INSERT/UPDATE/DELETE及事务行锁 |

C04只初始化网页动作权限，不执行数据库GRANT。原数据库账号如果是root通常已有权限；若使用受限账号，需要管理员按实际账号与Host配置：

- 已启用18表的SELECT；其他模块已有业务写权限保持。
- twin_scene：INSERT、UPDATE。
- twin_object：INSERT、UPDATE，克隆时复制对象并设置新父对象。
- twin_binding：INSERT、DELETE，保存时完整替换草稿绑定。
- audit_log：INSERT，记录克隆、保存与发布。
- site：UPDATE(id)列权限，用于SELECT FOR UPDATE的站点行锁。实际代码只锁定站点，不修改站点ID或台账字段。

最后一项已在MySQL8.0.33真实验证：仅SELECT的受限连接账号无法完成站点行锁。可由MySQL管理员参考如下语句，仅替换成你实际的后端数据库账号和Host：

```sql
GRANT UPDATE(id) ON smart_power_twin.site TO '你的后端MySQL账号'@'实际Host';
```

不要原样执行占位账号示例，也不要把网页sim_admin当MySQL连接账号。只有需要场景管理的后端连接才需这些写权限；只读展示模式仍可保持只读。

## 6. 七个接口

统一前缀`/api/v1`。先登录取得Bearer令牌，在Swagger的Authorize填写accessToken。

| 方法与路径 | 用途 | 网页动作权限 |
| --- | --- | --- |
| GET /scene-templates | 六类模板及资源制作状态 | twin:read |
| GET /sites/{siteId}/scene | 本站当前发布模型、对象、设备与绑定 | twin:read＋本站范围 |
| GET /sites/{siteId}/scenes | 分页版本摘要 | twin:read；无发布权限仅返回当前版本 |
| GET /scenes/{sceneId} | 指定场景版本详情 | twin:read；草稿/归档另需twin:publish |
| POST /sites/{siteId}/scenes | 复制当前发布场景为新草稿 | twin:publish＋写开关 |
| PUT /scenes/{sceneId}/bindings | 完整替换草稿绑定 | twin:publish＋写开关 |
| POST /scenes/{sceneId}/publish | 校验并原子发布 | twin:publish＋写开关 |

模板ID、场景ID、对象ID、设备ID、测点ID都是独立的十进制字符串。不要用henan-service-01作数据库ID，也不要把deviceId传到objectId。

复制草稿请求体通常为`{}`，也可在Swagger指定已放在前端public/models中的整场景GLB：

```json
{"modelUrl": "/models/service_medium.glb"}
```

模型路径只允许本地`/models/ASCII文件名.glb`，不支持任意磁盘路径、路径穿越或外网URL。

保存绑定是完整替换协议，不是只改一条。先查询草稿详情，把需保留的绑定一起提交；空数组表示清空草稿绑定，清空后不能发布。

```json
{
  "bindings": [
    {
      "objectId": "从草稿objects复制的对象ID",
      "pointId": "同设备测点查询返回的ID",
      "propertyCode": "temperature",
      "mappingConfig": null
    }
  ]
}
```

上述占位内容应替换成实际数字ID。propertyCode是展示属性，pointCode才是实际测点编码，两者可以不同。响应的pointName、unit来自真实测点，不用映射配置冒充单位。mappingConfig只保存最多8192字节的JSON展示元数据，不执行脚本，也不在本版应用任意单位转换。

## 7. 为什么不会串站或破坏旧版本

- 每次查询和写入都校验站点范围；未知/越权统一404，避免泄露其他站点详情。
- 绑定对象必须属于当前草稿，测点必须同站同设备；别的场景对象ID不能混进来。
- 全部绑定先校验，再删除/插入；发现一条错误，整批不保存。
- 已发布或归档版本禁止直接改绑定，需要复制新草稿。
- 所有场景写入按“站点→场景”顺序锁定；MySQL读取当前版本和分配版本号使用锁定当前读，防止旧事务快照导致并发重号。
- 发布时先校验模板类型、规模、资源、GLB实际节点和绑定，再在同一事务归档旧版本并发布新版本。
- 数据库的current_slot生成列及唯一约束限制每站最多一个PUBLISHED。重复发布已是当前的同一版本可幂等返回，不能复活归档版本。
- 发布过程任何一步失败都会回滚，旧版本继续服务；不会先删除原模型或原场景。
- 前端切站、换账号、撤权、刷新场景时清旧数据，迟到响应不覆盖新场景。公开模板与私有场景请求分开。

GLB匹配采用精确节点优先，否则匹配最长完整下划线前缀；例如storage_01不能误匹配storage_010。分组节点及其子部件均可定位，模型点击和目录点击使用同一对象ID。

当前已接入整场景GLB选择、发布版本、对象设备身份、绑定测点及监测查询；现有第四版服务区与收费站模型文件未修改。

以下内容本轮没有实现，不应当作已完成：

- 在线建模、模型上传、独立对象GLB拼装及JSON位置/旋转/缩放编辑。当前保留GLB内置布局；发布会拒绝尚不支持的独立对象资源或JSON位姿覆盖。
- 新站点从零建立对象、切换模板版本的完整编辑器。当前管理入口基于已有已发布场景复制；首次样例场景由手动SQL准备。
- mappingConfig驱动的任意动画、材质脚本或单位换算；当前主要用于读数关联。
- S/L四套成品模型。它们仍为资源为空的DRAFT模板；目前复用既有两套M模型。
- 告警自动评估及大屏统计。站点总负荷/能耗/告警仍明确为示意，避免和数据库监测混为一谈。

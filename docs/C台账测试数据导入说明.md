## 3. 如何使用SQL

1. 在MySQL客户端打开 `smart_power_twin` 的SQL编辑窗口，使用一个没有其他未提交操作的新连接。
2. 打开 `C台账模块_测试数据.sql`，执行整个脚本。客户端需要支持 `DELIMITER`，数据库账号需要相应表的查询/插入和存储过程创建、执行、删除权限。
3. 脚本只补齐缺失的业务编码，不预设数据库自增ID，不覆盖已有名称、状态、额定参数、账号、密码或授权。
4. 末尾的查询会显示两站的区域数、设备数和各设备额定参数。新空台账导入后每站应为三个区域、四台设备；已有其他设备时数量可以更多。

当前库已经有这套资料，因此不必为了补数据重新导入。以后缺数据时可以重跑；成功执行后不会重复生成同编码站点或设备。

脚本不创建业务表。如缺表，应先核对已有建表文件，不要把“缺少表结构”和“表中没有记录”混为一谈。辅助存储过程只用于确保异常时回滚本批业务数据，正常结束后删除；没有关闭外键检查或使用 `INSERT IGNORE` 掩盖错误。

如果客户端遇到错误立即停止，临时过程可能尚未删除。先查看错误原因，不要重复执行半段SQL或手动改已有账号；需要清理时只处理脚本所创建的 `c_spt_seed_assets_test_20261015` 辅助过程。

## 4. 导入后为何前端可能仍看不到

- 登录用户必须有对应的 `user_site_scope` 授权。该脚本不自动扩权，也不会恢复之前撤销的授权。
- 当前前端按后端授权站点的业务编码匹配已有三维演示场景。任意新增一个不同编码站点，不会自动变成新的三维模型。
- 当前三维页面的设备展示和电力示例仍来自前端模板，数据库台账与模型对象/测点的绑定要在后续 `twin`、`monitoring` 模块完成。
- 完全没有登录账号的空库，需要另行执行已有账号初始化流程；本文件不包含账号密码。

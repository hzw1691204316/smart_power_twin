# 三维场景创建与配置：实现与测试指南

更新：2026-10-18，后端版本0.8.0。项目：`D:\study_software\PythonProject\smart_power_twin`。

## 1. 本轮完成什么

补齐了“有站点台账，但还没有三维场景”的配置入口。现在可以从已发布模板创建本站草稿，手动关联模型对象与本站设备，再绑定设备测点，最后显式发布。原有“复制当前发布场景”的功能继续保留。

入口：登录后点击右上角用户名 → **三维场景配置**，地址 `/admin/scenes`。也可以在“站点与设备台账”选中站点，点击“配置本站三维场景”。账号至少需要 `site:read` 和 `twin:read` 才能进入页面。

保留全国/省市地图、海蓝主题、侧栏、面板收起缩放、登录会话和既有GLB资源。本轮没有修改模型文件或地图实现。没有向你的实际MySQL执行建表、导入或授权脚本。

## 2. 你可以先这样测试

### 先使用已有模拟站点，避免同时准备新站点资料

1. 重启后端；前端开发服务开启时会自动更新页面。
2. 用有 `twin:publish` 的管理员登录，从用户名菜单进入“三维场景配置”。
3. 选择朝歌服务区或朝歌收费站。已有的六站模拟数据都是中型，所以匹配中型模板。
4. 点击“复制当前发布版本”。这会复制现有对象和绑定生成一个新草稿，原大屏继续显示旧发布版本。
5. 修改一个对象的显示名称，点击“保存对象关系”。在对象与测点两个区域中，先保存一类修改再编辑另一类。
6. 在测点区域选择同设备的其他测点，或增加一个绑定，点击“保存测点绑定”。属性编码用小写英文字母开头，可含数字和下划线，同一对象内不能重复。
7. 确认后点击“发布此草稿”。原发布版本成为历史，本站只有一个当前发布版本。
8. 返回地图，重新进入本站三维页，点击对应设备，检查显示名称及测点。若三维页已经在其他标签页打开，点击“重新读取场景”或刷新该页；本轮没有做跨标签页实时推送。

### 测试完全从模板创建

选择站点后，在“与本站类型、规模匹配的已发布模板”中选择资源，点击“从模板创建草稿”。即使本站没有旧场景，也可以使用这个操作。

创建后，推荐对象的显示名初始为GLB键，设备关系全部为空。请修改名称并选择本站设备，再保存对象关系。这样不会把模型名称相似的对象错误地关联到另一台设备，也不会自动制造资产或测量值。

保存对象后，下面的绑定区域才会使用已经保存的设备ID加载测点。选择对象 → 增加绑定 → 保存测点绑定 → 发布。发布至少需要一个对象及一个有效绑定；空草稿可保存，但不能发布。

## 3. 新站点需要准备哪些数据

顺序是：**站点台账 → 设备台账 → 测点定义 → 场景对象关系 → 测点绑定 → 发布 → 采样接入**。

新建站点不会自动生成设备、测点或读数。设备在台账管理页新增；2026-10-18已补齐/admin/points测点管理页面，可从用户名、具体设备或场景配置页进入，详见《C测点管理页面_实现与测试指南.md》。下方保留等价API输入说明。

例如在后端 `http://127.0.0.1:8000/docs` 登录并填写Bearer令牌后，调用 `POST /api/v1/devices/{device_id}/points` 创建有功功率测点。`device_id`必须使用本站设备的数据库ID：

```json
{
  "code": "active_power",
  "name": "有功功率",
  "unit": "kW",
  "valueType": "NUMERIC",
  "aggregationType": "INSTANT",
  "sampleIntervalMs": 5000,
  "staleAfterMs": 15000,
  "enabled": true,
  "alarmLow": null,
  "alarmHigh": null
}
```

创建测点需要 `monitor:configure`；查看和选择测点需要 `monitor:read`。测点创建后回到配置页重载当前版本。只有定义、没有采样时，监测显示缺测，不会补成0。模拟设备和现场设备的采样来源继续分开。

## 4. 大型双侧服务区怎样用

大型服务区统一模板是 `SERVICE_L`，对应 `/models/service_large.glb`。若模板选择框中没有这个已发布版本，需要你手动导入已有 `C07大型服务区_统一模板注册.sql`。该脚本只注册模板，不自动改变站点规模、设备、授权或当前场景。

本站规模必须是L、类型必须是SERVICE，才能选择大型服务区模板。中型站点不能直接套大型模板。本轮也没有放开“已有场景站点修改规模”的台账限制，避免已有版本的类型/规模关系失效。

模板目录会提供38个功能对象键，其中34个是能源对象，另4个是雨棚或能源区结构。结构可以保持未关联设备，不影响它作为模型背景显示；不是38台实际设备。能源对象包括屋顶/车棚光伏、充电桩、变压器、储能柜、逆变器、电表和消防柜。根据真实台账逐个关联，不必为结构背景伪造测点。

小型服务区和大型/小型收费站等未制作、未发布资源的模板仍不可用。网页中的通用模型预览与授权站点的已发布业务场景是两个用途，不会互相替换。

## 5. 表之间是什么关系

仍使用原来的19张表，不新增业务表：

| 表 | 本功能的职责 |
| --- | --- |
| site / device | 站点类型、规模及本站设备身份；不由模型创建 |
| scene_template | 可复用的模型模板版本、GLB地址、推荐对象清单 |
| twin_scene | 某个站点的场景版本、状态和发布时间 |
| twin_object | 当前版本中一个GLB键对应的显示名称及可空设备ID |
| device_point | 某台设备的测点定义、单位和周期 |
| twin_binding | 一个场景对象的属性绑定到同设备的一个测点 |
| audit_log | 记录创建、对象编辑、绑定保存和发布操作 |

例如：北侧储能柜模型键 `storage_north_01` → 场景对象ID → 本站设备ID → 该设备SOC测点ID。模型键、对象ID、设备ID、测点ID各有职责，不能相互替代。

多个对象可关联同一设备，但不会因此变成多台设备或重复计算汇总功率。若一个模型对象代表整组设备，应先明确监测边界；本轮不自动把一组设备读数相加。

## 6. 保存、发布与保护规则

- 从模板创建与复制旧场景都会生成独立DRAFT；PUBLISHED和ARCHIVED不能直接编辑。
- 对象完整保存最多200个；同一场景内GLB键不能重复。推荐清单超过200个时，需先精简模板清单。
- 服务端核对实际GLB节点或完整下划线前缀；不是输入任意名称就能生成模型。
- 相同对象键保存时保留对象ID和测点绑定，修改显示名称不会导致已有绑定丢失。
- 删除对象或改变设备关系若影响绑定，返回409。先移除该对象的相关绑定并保存，再修改对象关系；不会静默删除测点关系。删除父配置时，保留子对象会解除父引用。
- 页面中“移除对象”只移除监测对象配置；GLB是整场景模型，因此不会把其中建筑或柜体网格从文件中删除。
- 当前沿用GLB内置位姿，不支持独立对象模型、拖拽摆放或JSON覆盖位置/旋转/缩放。
- 创建、编辑、发布按“站点 → 场景”顺序加锁。MySQL并发创建采用锁定当前读分配版本，防止重复版本号。
- 审计与业务写入在同一事务；失败时不留下部分对象或半个场景。并发编辑为串行保存后者生效，目前没有乐观锁或多人合并编辑。
- 页面有未保存内容时，切站/切版本/发布会禁用；“放弃修改并重载”可显式丢弃本地输入。离开页面、刷新或退出登录也会丢弃尚未提交的修改。
- 换账号、撤权、换站和页面卸载会使旧请求结果失效，不允许迟到响应把旧站点对象写回当前页面。

## 7. 新增接口和代码位置

前缀均为 `/api/v1`，请求/响应字段使用camelCase，数据库ID使用十进制字符串。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| GET /scene-templates/{template_id}/objects | twin:read | 复核实际GLB后返回模板推荐对象键；无清单时推荐外层命名节点 |
| POST /sites/{site_id}/scenes/from-template | twin:publish + 本站范围 | 从匹配的已发布模板创建草稿，返回201 |
| PUT /scenes/{scene_id}/objects | twin:publish + 本站范围 | 完整保存草稿对象关系 |

创建输入示例（ID只作协议示意，请替换成查询到的实际ID）：

```json
{
  "templateId": "7",
  "objects": [
    { "objectKey": "storage_north_01", "name": "北侧储能柜01", "deviceId": "501" }
  ]
}
```

对象保存只提交 `objects`，不提交templateId。对象字段只有objectKey/name/deviceId，不接受伪造isDemo、父关系或其他只读字段。isDemo继承站点/设备身份。

原接口 `POST /sites/{site_id}/scenes` **仍是复制当前发布版本**；原绑定保存、发布、版本查询接口保持含义不变。

## 8. 权限与常见提示

本轮复用现有动作权限，不新增权限编码，也无需新增建表SQL。若原ADMIN缺少三维权限，检查已有C04/C05权限脚本和角色配置，手动执行适用补丁后重新登录；不要为修权限重建数据库。观察员仍只读。

后端MySQL写开关需要启用。受限数据库连接账号还需原有SELECT权限、site行锁所需UPDATE(id)，以及twin_scene/twin_object/twin_binding的相应INSERT/UPDATE/DELETE和audit_log的INSERT权限。这是数据库连接账号权限，与网页登录账号角色不同；程序不会自行GRANT。

| 提示 | 怎么处理 |
| --- | --- |
| 没有可用模板 | 核对本站类型/规模、模板PUBLISHED状态和资源路径；大型服务区检查C07 |
| 缺少/无法解析GLB | 检查前端public/models文件与模板model_uri；不填写Windows绝对路径或外网URL |
| 对象已有测点绑定 | 先在测点区域移除相关绑定并保存，再删除对象或换设备 |
| 无可用测点 | 创建测点或检查monitor:read；必要时重载版本 |
| 没有发布按钮 | 观察员无twin:publish，或当前查看的是发布/历史版本 |
| 发布提示至少需要一个绑定 | 为已关联设备的对象增加有效测点绑定并保存 |
| MySQL只读 / 数据库查询失败 | 检查写开关和数据库连接账号权限，不需要重建表 |

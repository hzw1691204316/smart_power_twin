# 管理员与观察员：三维场景权限修复

日期：2026-10-17。

## 问题与原因

截图中央的提示由前端检测到当前身份没有 `twin:read` 时显示，场景请求尚未发出。这是网页登录账号的业务权限问题，与 MySQL 连接密码、显卡、模型文件本身无关。

原账号种子只初始化台账与账号管理权限；监测、三维模块后来分别增加 C03/C04 权限补丁。未导入时，原 ADMIN / VIEWER 角色没有新权限。此外，旧补丁记录首次执行标记，重复导入不会恢复之后被撤销的授权。

本次提供 C05 明确修复脚本，供你在自己的 MySQL 手动执行。未读取真实账号密码，也没有自动修改你正在使用的数据库。截图只能确认前端身份缺少权限，实际数据库角色仍应通过脚本结果核对。

## 执行方法

1. 使用平时执行 SQL 的数据库管理账号，打开同目录的 `C05管理员与观察员_模块权限修复.sql`。
2. 在 MySQL 客户端整份执行；脚本已指定 `USE smart_power_twin`，包含 `DELIMITER` 和存储过程，不能只执行选中间的 INSERT。
3. 确认无报错后看末尾两组结果：ADMIN 有三维查看与发布，VIEWER 有三维查看；第二组列出实际用户名、角色、状态和原授权站点数量。
4. 前端退出当前账号，重新登录 admin / viewer，再打开本人有权访问的站点。前端会重新读取身份与权限。通常不必重启后端。

| 能力 | ADMIN 管理员 | VIEWER 观察员 |
|---|---|---|
| 查看授权站点与设备 | 允许 | 允许 |
| 查看监测与当前发布的三维场景 | 允许 | 允许 |
| 维护测点、提交采样 | 允许 | 不授予 |
| 复制场景草稿、修改绑定、发布 | 允许 | 不授予 |
| 访问未授权站点 | 不扩大范围 | 不扩大范围 |

修复按角色编码 ADMIN / VIEWER 生效，因此覆盖两个角色下的所有用户，用户名可以是 admin、viewer 或原 mysql_admin、mysql_viewer。不会按名称自动改角色。若账号不在第二组结果中，先检查其实际角色；如果授权站点数为 0，应由管理员在账号管理中单独授权，不将角色权限与站点范围混为一谈。

## 修复边界

- 本脚本每次执行都会补回明确列出的缺失权限。以后若有意撤销这些权限，不要再次执行此修复；旧 C03/C04 的一次性语义保持不变。
- 不重置密码、状态、用户角色、站点范围，不重导入台账、读数或场景，不修改模型和地图样式。
- 不移除已有其他权限。如果 VIEWER 曾被人工错误赋予写权限，本脚本不负责撤销，应单独核查。
- 不对 MySQL 数据库连接账号执行 GRANT。未来管理员发布场景若收到数据库写权限错误，要单独检查后端数据库账号的写入与行锁权限。
- 不创建缺失表。若出现表不存在，先核对之前的建表脚本；不要为解决权限问题重新导入账号初始化或全量模拟数据。
- 若提示 `ROLE_REPAIR_EXPECTS_ADMIN_AND_VIEWER`，表示角色编码不符合原方案，事务回滚。不要随意新建同名用户或给所有站点授权。

## 如何验证

admin：进入已授权朝歌站点，三维模型可加载，点击设备后能查看绑定的测点；有发布权限时可进入场景版本管理。

viewer：进入本人已授权站点可查看模型与绑定读数，但不能创建、修改或发布场景。原来没授权的收费站仍然不可访问，这是正常的范围限制。

如果缺少权限的提示消失后出现“本站尚无发布场景”，说明权限已通过，但该站点还缺已发布的场景数据，应继续检查数据，而不是绕过授权。

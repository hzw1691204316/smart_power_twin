## 二、为什么刷新后原来要重新登录

原先 `src/stores/auth.ts` 只把登录令牌和当前用户放在 JavaScript 内存。F5 会重新创建应用，令牌变成空字符串，路由守卫立即跳转到登录页。这个问题与 MySQL 密码和跨域无关。

现改为当前标签页会话恢复：

1. 登录成功后，`sessionStorage` 保存短期令牌及绝对过期时间，不保存账号密码、用户详情、角色或权限。
2. 刷新时路由先等待恢复会话，再请求 `/api/v1/auth/me`，由后端验证令牌、账号状态和最新权限。
3. 核验成功留在原来的页面，例如河南路网、鹤壁路网或朝歌三维页面；不再要求重复输入账号密码。
4. 刷新不会延长令牌期限。当前默认有效期仍为30分钟，以实际后端配置为准；期限内刷新可恢复，过期仍需登录。本次没有增加自动续期。
5. 点击退出、令牌过期、账号停用/锁定造成401时清除会话。清除只针对本系统的存储键，不清浏览器其他数据。
6. 后端短暂离线或数据库暂不可用不直接删除有效会话。刷新时如果无法核验，登录页提供“重新验证登录状态”，后端恢复后可重试，不必再次输入密码。

`sessionStorage` 对同一来源、当前标签页的刷新生效。`localhost` 与 `127.0.0.1`、不同端口属于不同来源；建议固定使用同一个地址。通常关闭标签页后会话结束，部分浏览器恢复标签页时可能恢复会话，但后端仍会检查令牌期限。暂不实现跨设备登录保持或“记住我”。

## 三、代码职责与后续修改位置

| 文件 | 实现的功能 |
| --- | --- |
| `src/services/authSession.ts` | 封装读写/清除标签页会话，检查记录格式与到期时间；存储禁用时回退普通内存登录。 |
| `src/stores/auth.ts` | 登录、退出、绝对期限计时、恢复会话、后端身份核验；防止迟到的旧请求恢复已退出的账号。 |
| `src/router/authGuard.ts` | 首次导航等待会话核验，再判断登录和动作权限；与路由表拆开便于测试和维护。 |
| `src/router/index.ts` | 保留既有路由，注册上述守卫。 |
| `src/views/LoginView.vue` | 正常账号密码登录；临时离线会话的重试按钮；仍无临时密码提示。 |
| `scripts/check-auth-session.mjs` | 使用真实 Pinia store、Vue 路由守卫及 HTTP 适配模拟刷新场景。虚拟令牌与测试用户，不访问真实库。 |

新模块和主要函数已补充中文说明。后端接口、MySQL结构、账号密码和数据库配置均未修改，不需要执行SQL。

你可按以下步骤检查：

1. 更新前端后登录一次，让新版本写入会话记录（旧内存令牌无法在刷新后找回）。

3. 点击退出，再刷新，确认需要重新登录。
4. 令牌到期或账号停用时确认会退回登录页。
5. 若后端未启动，先恢复后端连接，再点“重新验证登录状态”。本次没有继续处理此前暂停的MySQL服务启动问题。
